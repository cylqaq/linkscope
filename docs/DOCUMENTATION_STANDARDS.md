# LinkScope · 文档规范与边界

> 本文档定义 LinkScope 项目的文档规范、边界限制和更新流程，确保文档体系的一致性和可靠性。

## 1. 文档体系概述

### 1.1 文档分类

| 文档 | 用途 | 更新频率 | 维护者 |
|------|------|----------|--------|
| `AGENTS.md` | Agent 接力指南 | 每次迭代 | 开发团队 |
| `docs/ARCHITECTURE.md` | 系统架构设计 | 重大变更时 | 架构师 |
| `docs/DECISIONS.md` | 决策记录（仅追加） | 每次决策 | 开发团队 |
| `docs/AI_DEVELOPMENT.md` | AI 开发指南 | AI 相关变更 | AI 工程师 |
| `docs/MCP_INTEGRATION.md` | MCP 集成指南 | MCP 相关变更 | 集成工程师 |
| `docs/LOOP_ENGINEERING.md` | Loop Engineering 指南 | 流程变更 | DevOps |
| `docs/upgrade-plans/CURRENT.md` | 当前迭代计划 | 每次迭代 | 项目经理 |

### 1.2 文档层级关系

```
AGENTS.md (入口)
    ├── docs/ARCHITECTURE.md (架构)
    ├── docs/DECISIONS.md (决策)
    ├── docs/AI_DEVELOPMENT.md (AI)
    ├── docs/MCP_INTEGRATION.md (MCP)
    ├── docs/LOOP_ENGINEERING.md (流程)
    └── docs/upgrade-plans/CURRENT.md (计划)
```

## 2. 文档更新规范

### 2.1 必须更新文档的场景

**架构相关**：
1. 新增或修改分层（L1/L2/L3）
2. 新增或修改数据契约（`Evidence`、`ReasonCode` 等）
3. 新增或修改扩展点
4. 新增或修改性能基准

**AI 相关**：
1. 新增 AI 模型提供商
2. 修改系统提示词
3. 添加新工具
4. 修改融合策略

**MCP 相关**：
1. 新增 MCP 工具
2. 修改工具参数
3. 新增资源类型
4. 修改传输协议

**流程相关**：
1. 新增验证脚本
2. 修改循环流程
3. 新增 Skills 或 Hooks
4. 修改状态管理逻辑

### 2.2 更新流程

**标准更新流程**：
```
1. 修改代码前先读 DECISIONS.md 相关条目
2. 修改代码
3. 运行验证脚本（scripts/verify.sh）
4. 更新本文档对应章节
5. 在 DECISIONS.md 追加新条目（D-NNN）
6. 必要时更新其他相关文档
7. 提交代码
```

**紧急更新流程**：
```
1. 修复问题
2. 运行验证脚本
3. 更新 DECISIONS.md
4. 提交代码
5. 后续补充其他文档更新
```

### 2.3 文档版本控制

**版本格式**：`主版本.次版本.修订版本`
- 主版本：重大架构变更（不向后兼容）
- 次版本：新增功能或模块
- 修订版本：错误修复或小优化

**版本记录位置**：
- 主版本/次版本：`DECISIONS.md` 新增条目
- 修订版本：各文档修订历史章节

## 3. 文档边界限制

### 3.1 禁止的行为（NEVER）

**文档内容**：
1. 不记录敏感信息（API Key、密码、内部 IP 等）
2. 不记录过时的信息（必须及时更新）
3. 不记录未经验证的假设
4. 不记录重复的信息（保持唯一来源）

**文档格式**：
1. 不使用模糊的描述（必须具体明确）
2. 不使用过时的术语（必须使用当前术语）
3. 不使用不一致的格式（必须遵循模板）
4. 不使用过长的段落（必须分点说明）

**文档维护**：
1. 不跳过文档更新（代码变更必须同步文档）
2. 不删除历史记录（只能追加，不能修改）
3. 不留下未完成的文档（必须及时完成）
4. 不留下错误的文档（必须及时修正）

### 3.2 必须遵循的规范

**内容规范**：
1. **准确性**：文档必须与代码保持一致
2. **完整性**：文档必须覆盖所有关键点
3. **清晰性**：文档必须易于理解
4. **时效性**：文档必须及时更新

**格式规范**：
1. **结构清晰**：使用标题、列表、表格
2. **代码示例**：提供可运行的代码示例
3. **图表说明**：复杂逻辑使用图表说明
4. **版本标注**：标注文档版本和更新时间

**维护规范**：
1. **定期审查**：每季度审查一次文档
2. **及时更新**：代码变更后立即更新文档
3. **版本控制**：文档纳入版本控制
4. **备份策略**：重要文档定期备份

## 4. 文档模板

### 4.1 技术文档模板

```markdown
# 文档标题

> 简短描述文档的目的和范围。

## 1. 概述
- 目的
- 范围
- 读者

## 2. 核心概念
- 关键术语
- 核心原理

## 3. 详细说明
- 分点详细说明

## 4. 示例
- 代码示例
- 使用场景

## 5. 最佳实践
- 推荐做法
- 避免事项

## 6. 参考资源
- 相关文档
- 外部链接
```

### 4.2 决策记录模板

```markdown
## D-NNN · 决策标题（Round N）

**问题**：描述问题背景

**决策**：描述决策内容

**理由**：描述决策理由

**影响**：描述决策影响

**实现锚点**：相关代码位置
```

### 4.3 迭代计划模板

```markdown
## 计划题目（YYYY-MM-DD · Round N · 简短主题）

- **问题**：描述当前问题
- **目标**：描述迭代目标
- **拟措施**：描述具体措施
- **风险/不做的事**：描述风险和边界
- **验收标准**：描述完成标准
```

## 5. 文档质量检查

### 5.1 检查清单

**内容检查**：
- [ ] 文档是否与代码一致
- [ ] 文档是否覆盖所有关键点
- [ ] 文档是否易于理解
- [ ] 文档是否及时更新

**格式检查**：
- [ ] 文档结构是否清晰
- [ ] 代码示例是否可运行
- [ ] 图表是否准确
- [ ] 版本是否标注

**维护检查**：
- [ ] 文档是否纳入版本控制
- [ ] 文档是否有备份
- [ ] 文档是否有审查机制
- [ ] 文档是否有更新流程

### 5.2 质量指标

**必须满足的指标**：
- 文档覆盖率：≥ 90%
- 文档准确率：≥ 95%
- 文档更新及时率：≥ 90%
- 文档审查通过率：≥ 95%

**监控指标**：
1. 文档变更频率
2. 文档审查时间
3. 文档错误率
4. 用户反馈

## 6. 文档工具与自动化

### 6.1 文档生成工具

**推荐工具**：
- **Markdown**：主要文档格式
- **Mermaid**：图表绘制
- **Swagger/OpenAPI**：API 文档
- **JSDoc/TSDoc**：代码文档

**自动化流程**：
1. 代码变更自动触发文档检查
2. 文档变更自动触发审查
3. 文档发布自动生成版本
4. 文档错误自动告警

### 6.2 文档审查工具

**推荐工具**：
- **markdownlint**：Markdown 格式检查
- **vale**：文档风格检查
- **proselint**：文档质量检查
- **Grammarly**：语法检查

**审查流程**：
1. 提交前自动检查格式
2. 提交后自动检查质量
3. 定期自动检查一致性
4. 发布前自动检查完整性
